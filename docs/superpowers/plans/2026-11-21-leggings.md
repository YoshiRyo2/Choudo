# Leggings (PR 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every code task is test-first (superpowers:test-driven-development).

**Goal:** Add a `leggings` template: negative-ease girth zones (waist, hips, thigh, calf) as a share of the body, compression stretch per zone, length as a landing against the body's ankle, a skin-tight drawing on the pants template, and two Sport-Tek women's rows.

**Architecture:** The engine already supports fraction-scale `GirthRule`s, per-zone stretch allowances and landing zones (PR 1a/1b). Leggings are a new `TemplateZones` entry plus rules, one new body key (`ankleHeightCm`), one new garment key (`calf`), a `CategorySpec`, and `templates/leggings.ts`. Category stays `bottom`. No `legwear` slot yet, so nothing can be worn over leggings.

**Tech Stack:** TypeScript, Vitest, React SVG (existing).

**Spec:** `docs/clothing-categories-design.md` §2.3, §5 (ankle), §6 "PR 7 — leggings", plus Ryo's brief (2026-11-21).

## Global Constraints

- New thresholds ship labelled **"assumed"** in their doc comments (decision 1).
- **Every existing garment's golden lines stay byte-identical.** Only new lines for the new rows may appear. Check: `git diff -U0 app/src/domain/fit/__golden__ | grep '^-[^-]'` prints nothing.
- Skin rule: every height or width the leggings drawing uses comes from `BodyModel`, the garment, or a `domain/fit` function.
- Missing or unverified measurements give `unknown`, never a guess. Rows not from a real chart are `placeholder: true`. No product photos (`images` absent, `landmarks: null`).
- New body keys go at the end of `LEG_KEYS`, and new garment keys at the end of `MEASUREMENT_KEYS` (sampler streams).
- `npm run check` exits 0 before every commit. Never commit `node_modules/`, `.vitest`/`.vite` caches or `app/.models/`.
- Cloud setup: `npm ci --ignore-scripts && npm rebuild esbuild`.

## Decisions for Ryo (my recommendation first; the plan assumes it)

1. **LPST880 as the second row.** SanMar sells it as a "fitness pant", but it is spandex and cut about 15 % under the body at the hip (XS 29½ in round vs a 34–36 in body hip). It's the only Sport-Tek women's chart I found with a hip measurement, and I could not reach a LPST891 page. Type `leggings`, with the name kept as printed.
2. **LPST880's hip is read as flat.** No method is printed for the hip row, but the waist row in the same table is "laid flat", and 14¾ in can't be a full circumference (stage-5 would error). `chart.girth: "flat"`, with this reasoning in `source.notes`.
3. **Hips stay required** (as pants). LPST890 has no hip, so its overall result is `unknown` and `recommendSize` is null, with the waist and length still shown. The other choice is to make hips optional for leggings.
4. **A fourth length mark, `stacked`** (tone warn), for a hem more than 4 cm past the ankle bone. LPST880's 31 in inseam on a 163 cm body lands about 7 cm past it. Without this mark it would read "ankle".
5. **The drawn ankle moves to the body's ankle height** (`y.ankle = H − ankleHeightCm`, was `0.955 H`, about 1 cm higher) so an "ankle" hem is drawn at the ankle. Drawing snapshots for bottoms and dresses update and I review them. Fit golden files don't change.
6. **No knee zone.** The design doc lists one, but your brief says waist, hips, thigh, calf.

## Review Focus

1. A legging with stretch `high` rather than `compression` (cotton–spandex): "tight" must start sooner (−13 %, not −18 %). Pinned in Task 3.
2. A chart bigger than the body (a "relaxed" legging): +5 % hips reads `loose` ("baggy"), and the drawing widens to the chart instead of staying skin-tight. Pinned in Tasks 3 and 6.
3. A men's body choosing "All" and seeing a women's legging: the ankle height comes from `MENS_LEG_RATIO`, and the zones still score. Pinned in Task 1 (men's key) and Task 4 (golden men's bodies).
4. An entered inseam much shorter than the estimate: the ankle must stay below the knee (`orderHeights`), and the landing uses the entered inseam. Pinned in Task 1.
5. LPST890 with no hips: the size is `unknown`, the readout says why, and `recommendSize` returns null rather than picking on the waist alone. Pinned in Task 4.

**Interfaces (produces):**
- `crotchToAnkleCm(m: BodyMeasurements): number` = `m.inseamCm − m.ankleHeightCm`
- `leggingsHemHeight(m: BodyMeasurements, size: SizeMeasurements): number | null` = `m.inseamCm − size.inseam`, or null without an inseam (the drawing reads this)
- `LEGGINGS_WAIST`, `LEGGINGS_GIRTH: GirthRule`, `LEGGINGS_LENGTH: LandingRule`

Rules, all **assumed** (to tune with Test mode), with fraction scale. The effective tight boundary is `tightBelow − allowance`:
- `LEGGINGS_GIRTH` (hips, thigh, calf): `tightBelow −0.05, fittedMax −0.02, relaxedMax 0.03, ideal −0.08`, `stretch: { none: 0, some: 0.04, high: 0.08, compression: 0.13 }`. Tight is then −18 % at compression and −13 % at high. Comment: the design doc's ideal −8 % / tight −18 %; LPST880 cut ≈ −15 % at the hip.
- `LEGGINGS_WAIST`: `tightBelow −0.04, fittedMax 0.04, relaxedMax 0.08, ideal 0`, `stretch: { none: 0, some: 0.02, high: 0.04, compression: 0.06 }`. Comment: both charts' relaxed waistbands are cut at about the body's (LPST890 M 29 in vs a 29–30 in waist). A band holds up; it isn't compressed like the leg.
- `LEGGINGS_LENGTH` (inseam − crotch-to-ankle): `capri −∞`, `7/8 −16`, `ankle −5`, `stacked +4 (tone warn)`.

`LEGGINGS_ZONES`, in order:
- waist: the pants waist spec with rule `LEGGINGS_WAIST` (band at `bandHeight(riseForBand)`, so the navel without a rise)
- hips: `LEGGINGS_GIRTH`, required
- thigh: as pants (optional, needs `definitions.thigh`), rule `LEGGINGS_GIRTH`
- calf: `garmentKey 'calf'`, `bodyKey 'calfCm'`, `LEGGINGS_GIRTH`, optional
- inseam: landing, `bodyTarget: crotchToAnkleCm`, `bodyAt: 'ankle'`

`personal: null`.

**Interfaces:** `leggingsShape(g: BodyGeometry, body: BodyMeasurements, garment: Garment, size: SizeMeasurements): BottomShape` (the pants return type, so the Mannequin path is unchanged).

Shape: the band at `bandHeight(body, riseForBand(garment, size))`, the hem at `H − leggingsHemHeight` (full to the ankle when null, dashed). Each leg follows the body's leg outline (`g.leg`: thigh, knee, calf, ankle half-widths) plus 0.2 cm, with no folds. At hips, thigh and calf, the half-width is `max(body + 0.2, halfWidth.leg(chart girth))`, so a chart bigger than the body draws wider. Width at the hem is the leg's own width at that height (interpolated). `approximate` is true when the hem has no inseam.
