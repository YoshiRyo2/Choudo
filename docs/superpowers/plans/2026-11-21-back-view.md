# Back View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Front/Back toggle in the Fitting room that turns the mannequin and every garment it wears to show the back, using a garment's back photo when it has one that may be warped, and the same template without front-only details when it doesn't.

**Architecture:** The body model and the fit stay exactly as they are; `view` is a drawing option only. Each template that has a front-only detail (`topShape`: neckline and hood; `jacketShape`: placket and collar opening; `dressShape` via its bodice) takes `view` and returns the same outline points, markers and sleeve edges as the front, so pins sit at the same heights. Pants, shorts, skirts and leggings draw the same outline from both sides and take no `view`. A garment gets an optional `backImage` (same `GarmentImage` shape, same licence rules). The Mannequin picks `image` or `backImage` by view and never puts the front photo on the back.

**Tech Stack:** React 19 + TypeScript + Vite, Vitest, plain SVG. No new dependencies.

**Spec:** the task brief (Front/Back toggle; back photo + landmarks + licence; fit unchanged; skin rule; data:check), read with `CLAUDE.md`, `docs/clothing-categories-design.md` (§2.4, §3.2, "as built" notes) and `docs/parked-ideas.md` (skin rule).

## Global Constraints

- Golden fit files `app/src/domain/fit/__golden__/` stay byte-identical: `git diff --exit-code app/src/domain/fit/__golden__` after every task. (`garments.json` serialises every garment, so **no seed garment gets a `backImage` in this PR**; there are no back photos yet.)
- Existing drawing snapshots (`topShapeGuard`, `skirt`, `tee-warp-*`, jacket/knit/dress tests) stay unchanged: the front view is the default everywhere and draws exactly as today.
- Skin rule: body proportions identical in both views. `bodyGeometry` gets no view parameter; every height and width in the back view is the front's.
- Fit is the same front and back: nothing in `domain/fit/` changes; FitStrip/FitReadout don't see `view`.
- Back photos follow `PHOTO_LICENCES` / `canWarp` exactly as front photos; a `local-only` back photo is never warped in the app and never ships (`localOnlyFiles`).
- Without a back photo the back is drawn in flat colour from the template: no collar placket, no front neckline dip, no hood front edge or drawcords, and never the front photo (no front graphic).
- `npm run check` (from `app/`) must exit 0 before every commit. Don't commit `node_modules` or cache folders.
- Cloud setup if needed: `npm ci --ignore-scripts`, then `npm rebuild esbuild`.

## Decisions taken in this plan (flag any you want changed)

1. **Back landmarks reuse the front names**, viewer-relative ("Left" is the viewer's left in the back photo too), except tops: `neckFront` becomes **`neckBack`** (the bottom of the back neckline). Pants keep their 14 names (`waistMid` = centre back, `crotch` = back crotch). Knits' `hoodTop` is front-only. Jackets, skirts, shorts, dresses and leggings still take no photo (`landmarks: null`), so no back photo either.
2. **Back neckline** sits `BACK_NECKLINE_DIP_CM = 1` (skin, assumed) under `g.y.neckBase` (front: 3.5, or 1.5 for collared types). In the back view `TopShape.landmarks.neckFront` holds that centre-back point (the mesh slot is "centre neckline of the side drawn"; renaming it would change the seed and the golden file).
3. **Hood in the back view** lies flat on the upper back (`hoodOnBack` path, skin constant `HOOD_BACK_DROP_CM = 22`, assumed), drawn over the top — and over a jacket worn on top, since a hood comes out over a jacket's collar.
4. **Pins** come from the back drawing's markers (equal to the front's), on the same viewer sides as the front (top/jacket right, bottom left).
5. **The toggle isn't stored**: plain `useState`, opens on Front each visit. No storage key changes.
6. **Back cut-outs** are configured in `scripts/garment-photos.json` with `"side": "back"`; the default output is `public/garments/<id>-back.png`.

## Review Focus

1. A garment with a front photo and no back photo (the navy graphic tee, the grey polo) shown from the back → flat colour, front photo not warped onto the back. Pinned in Task 5 (`viewPhoto` test).
2. A `local-only` back photo → never warped in the app and listed by `localOnlyFiles` so `dist:check` keeps it out of the build. Pinned in Tasks 1 and 5.
3. A back photo saved with the front's names (`neckFront`, or a knit's `hoodTop`) or on a template with no landmarks (a jacket) → `data:check` error naming the problem. Pinned in Task 1.
4. Jacket over a hoodie from the back → jacket hangs off the back-drawn hoodie with the same widths as the front, the hood shows over it. Pinned in Task 4 (jacket markers equal front's) and checked in the browser in Task 6.
5. A dress worn, then Back → bodice gets the back neckline, skirt and pins unchanged. Pinned in Task 4.
